# N1 Data Contract

Version 1.2 (version 1.1 extended with a correction layer, dividend_basis and dividend_correction_source columns, a local source, and evidence for the absence of distributions; version 1.0 extended to reflect the N1 implementation: issuer sources, distribution units, tolerance, and the actual-payable condition). Implements research protocol 1.0 without changing its economic rules. Final eligibility is determined by docs/n1/N1_REPORT.md, not by the existence of CSV files. This is an editorial English translation at baseline `4516269`; see [Documentation edition](docs/DOCUMENTATION_EDITION.md).

## Scope and layers

The protocol's ten ETFs; USD only. Daily regular sessions in America/New_York through 2026-10-05 inclusive. Common history begins on 2007-05-30; history before 2009 is used for warm-up. Requests retain available earlier history separately; tradable history is not synthesized.

Local data/snapshots/<run_id> directories contain original responses and original adapter tables; data/derived/<run_id> contains normalized tables and QA. Each directory is created once and contains manifest.json, a SHA-256 list for every file, and manifest.sha256. A repeat creates a new directory. Verification rejects changed/deleted/added files, unsafe paths, and manifest changes. This detects modification; it is neither a cryptographic signature nor protection against coordinated falsification of all files and logs.

Correction layer: data/corrections/<run_id>/{corrections.json, payable.json}. For each ticker and ex-date, corrections.json contains an action (add, replace, remove), the Yahoo amount (null for add), the issuer's as-traded amount, the issuer's payable_date (null for remove), and a source reference with the file's sha256 in the evidence snapshot. Construction rules: issuer_only produces add; amount_mismatch produces replace; yahoo_only produces remove only when the issuer has an explicit zero row on that ex-date, otherwise no correction; matched is not corrected. Freeze the file as a separate vintage with a manifest; the original Yahoo snapshot remains unchanged. A derived snapshot built with corrections contains its own corrections.json, and replay rebuilds its tables with that file; substitution of the correction file fails replay.

Original HTTP bodies are stored without Cookie/Authorization headers or query credentials. The original chart may contain current administrative metadata outside the chosen period; only requested sessions enter normalization. Snapshots are not committed. The append-only attempt log records outcome/error, git SHA, dirty patch and untracked-file hashes, config/environment/data hashes, parent, seed, and exact temporal roles. Seed=null with reason deterministic_data_pipeline; candidate_ids is empty and strategy returns are not calculated.

## Adapter

yfinance with interval=1d, auto_adjust=False, back_adjust=False, actions=True, repair=False, keepna=True; start=1990-01-01, end=2026-10-06. The original Yahoo chart JSON is captured separately. Versions are pinned in requirements.lock. An empty response, incomplete columns, or missing original body is an error, not a successful empty dataset.

Table grain is one row per ticker × session. session is unique and increasing. OHLC and Adj Close are finite and positive; Low <= Open/Close <= High. Volume is finite and nonnegative. Dividends/Capital Gains >=0; Stock Splits=0 means no event, while a positive value means new/old shares. Incomplete, duplicate, non-session, or missing bars are not silently repaired. An unexpected action without an eligible bar blocks normalization.

## Units and distributions

Yahoo OHLC are verified as split-adjusted, without dividend adjustment. Once the basis is confirmed, multiply raw OHLC by the product of strictly subsequent split ratios. The split date is already on the new basis. If a split and dividend share a date, the dividend is treated as a per-share amount after the split, with multiplier 1 (tests/test_normalize.py, test_forward_split_plus_same_day_dividend_no_double_count). Dividend units also require separate verification; a correct split event does not establish the distribution basis.

source_volume remains in source units, labeled unconfirmed; it is not used for execution, liquidity limits, or quantity selection. An unverified volume reconstruction must not be represented as as-traded volume.

The normalized table explicitly retains source_close, source_adj_close, source_dividend, split_ratio, future_split_factor, as-traded OHLC, and as-traded dividend. The dividend_basis column is `source` or `issuer_correction`; dividend_correction_source is empty if the amount is unchanged, otherwise it contains the issuer source reference. In a corrected row, dividend equals the issuer amount (0 for remove), while source_dividend retains the original Yahoo value. A correction whose ex-date is not a table session or whose yahoo_amount differs from the original event raises an error; corrections do not change prices or splits, and TR changes only from the corrected session onward. Theoretical TR: T0=1; Tt/Tprev = split_ratio_t × (close_t + dividend_t)/close_prev. An initial event without a preceding price does not create a fictitious return. This quantity supports features; in N2 the portfolio receives a separate receivable and cash on payment.

Actual payable requires a source URL/hash and an issuer date matching the ex-date. The implementation uses it only for an event whose amount matches the issuer, and only when payable is no earlier than ex-date; otherwise it uses the proxy. Cash-credit session is the first regular session no earlier than payable. If actual is unavailable: ex-date +10 calendar days and the first session on/after it; sensitivities +0/+30 are supported through a separate parameter. The calendar extends beyond the cutoff for future payments; future prices are not added. Missing actual payable is permitted by the protocol; an unknown distribution amount/basis is not.

## Timing and causality

available_at is 18:00 America/New_York on session, including early closes; availability_basis=historical_model_assumption. retrieved_at is the actual UTC timestamp. Modeled historical availability does not establish point-in-time publication. Prospective data in N2+ will require actual retrieval timestamps without backdating.

As-traded reconstruction uses future split events solely to reverse the provider's retrospective unit changes. A synthetic test adds a future split together with the corresponding rebasing of source prices/dividends and requires past as-traded prices and TR to remain unchanged. This does not protect against future provider revisions: those receive a new vintage.

## Calendar, QA, and eligibility

exchange-calendars XNYS, including exceptional closures and early closes; it serves as a common US regular-session calendar and is checked for every ETF. Separate tests cover Sandy 2012-10-29/30, the Thanksgiving early close, and a weekend payable date. Completeness is checked against expected sessions from the common start to cutoff, rather than solely through the intersection of observed rows.

Corporate events are independently reconciled for EEM 2008-07-24 (3:1) and BIL 2017-11-30 (1:2); distributions of all distributing ETFs are reconciled with the issuer. Sources: SSGA historical-distribution xlsx files (SPY, BIL; as-traded amounts, dividend + short- and long-term capital gain) and iShares product pages (EFA, EEM, IEF, TLT, LQD, HYG; totalDistribution in current share units, converted to as-traded using the same future_split_factor as Yahoo). Amount tolerance is 0.0005 USD × max(1, future_split_factor) in as-traded units (D013).

For DBC, issuer evidence is a local capture of Invesco JSON (source type `invesco_json`, as-traded amounts): the file is in data/manual, read relative to the project root rather than downloaded from the network, and copied into the evidence snapshot after checking the sha256 declared in configuration; a hash mismatch is an evidence-acquisition error. For GLD, the source is an SSGA document with no_distributions, statements (quotation and page), and basis fields; confirmed_no_distributions is assigned only if Yahoo has no events for the ticker in the window, otherwise unresolved. Without a source, status is unverified_no_issuer_source. comparison.json records issuer_zero_dates for each ticker: the ex-dates of explicit issuer zero rows.

Reconciliation with corrections (`reconcile --corrections`) applies corrections.json to the original table and compares the result with the issuer under the same rule; the log records the correction file hash and path and, if the file is in a frozen vintage, its run identifier. Split documents: PHLX series adjustment 1410-08 (EEM) and IRS Form 8937 (BIL). Adj Close is an additional source diagnostic, not an independent provider or a substitute for explicit actions. Different reinvestment rules may produce small discrepancies: compare both the Adj/Close change factor against Yahoo's dividend adjustment and the economic TR separately; large unexplained jumps block actual N2 calculations.

Final statuses distinguish technical reproducibility, calendar completeness, an established action basis, and permission to use the data. Completeness of all historical distributions cannot be inferred from row counts. All material exceptions and manual decisions are disclosed in the report and DECISIONS.md.
