# N2: ручные сверки механики исполнения

Основание: спецификация docs/superpowers/specs/2026-10-07-n2-execution-design.md, разделы 5, 6, 8 и 9; RESEARCH_PROTOCOL.md §8. Каждый случай посчитан вручную до запуска движка; тест в tests/test_engine.py сравнивает значения движка с этими числами через `pytest.approx(значение, abs=1e-9)`, целые количества и строковые поля сравниваются точно.

## Общие условия

- Календарь: сессии XNYS 2017-11-27 … 2017-12-08 (десять сессий: 11-27, 11-28, 11-29, 11-30, 12-01, 12-04, 12-05, 12-06, 12-07, 12-08). Данные синтетические (tests/n2_fixtures.py), `payable_basis = actual`, если не указано иное.
- Базовый сценарий: издержки c = 0.001, lag = 1, резерв r = 0.01, proxy_pay_days = 10. Начальные деньги 100000.0, позиций нет.
- start_session равна первой дате решения, end_session = 2017-12-08. Даты решений заданы явно.
- Размер заявки: Q = floor((1 − r) × w × NAV / close), множитель (1 − r) = 0.99.
- Продажа: выручка = qty × open × (1 − c). Покупка: расход = qty × open × (1 + c). Издержки = c × qty × open.
- Покупки: R = Σ q × open × (1 + c), fill = min(1, cash / R), покупается floor(fill × q).
- Поставщик весов возвращает вес по каждому тикеру рынка; тикер, не названный в случае, получает вес 0.

## Случай 1. До и после открытия

Вход: тикер AAA, close 100 во все сессии, open 100 во все сессии, кроме 2017-11-29 (open 100.5). Решение 2017-11-28, вес AAA = 1.

Расчёт:

1. Q = floor(0.99 × 1 × 100000 / 100) = floor(990.00) = 990; заявка +990 на 2017-11-29.
2. Покупка 2017-11-29: 990 × 100.5 = 99495.0; издержки 99495.0 × 0.001 = 99.495; расход 99495.0 + 99.495 = 99594.495.
3. Деньги: 100000 − 99594.495 = 405.505.
4. NAV на закрытии 2017-11-29: 405.505 + 990 × 100 = 99405.505.

Ожидаемые значения: target_qty 990, qty заявки 990, close заявки 100; сделка 2017-11-29, buy 990 по 100.5, cost 99.495; деньги 405.505; NAV 99405.505.

Изменение. Close и open сессий 2017-11-30 … 2017-12-08 заменены (250 и 17). Заявка решения 2017-11-28 использует только close 2017-11-28 и open 2017-11-29, поэтому target_qty (990) и close (100) совпадают с исходным прогоном.

## Случай 2. Сплит 1:2 (ratio 0.5) с позицией и висящей заявкой

Вход: тикер BBB, close и open 91 до 2017-12-04 включительно, split_ratio 0.5 на 2017-12-05, close и open 182 с 2017-12-05. Решения: 2017-11-28 (вес 1), 2017-12-04 (вес 0.5), 2017-12-06 (вес 0).

Расчёт:

1. Решение 2017-11-28: Q = floor(0.99 × 100000 / 91) = floor(1087.91) = 1087; заявка +1087 на 2017-11-29.
2. Покупка 2017-11-29: 1087 × 91 = 98917.0; издержки 98917.0 × 0.001 = 98.917; деньги 100000 − 98917.0 − 98.917 = 984.083.
3. NAV на закрытии 2017-12-04: 984.083 + 1087 × 91 = 984.083 + 98917.0 = 99901.083.
4. Решение 2017-12-04: Q = floor(0.99 × 0.5 × 99901.083 / 91) = floor(49451.036 / 91) = floor(543.42) = 543. Заявка 543 − 1087 = −544 на 2017-12-05.
5. Сессия 2017-12-05, шаг 1 (сплит, ratio 0.5): позиция 1087 × 0.5 = 543.5; заявка −544 × 0.5 = −272. Деньги не меняются.
6. Продажа 2017-12-05: 272 по 182; 272 × 182 = 49504.0; выручка 49504.0 × (1 − 0.001) = 49454.496; деньги 984.083 + 49454.496 = 50438.579; позиция 543.5 − 272 = 271.5.
7. NAV на закрытии 2017-12-06: 50438.579 + 271.5 × 182 = 50438.579 + 49413.0 = 99851.579. Решение 2017-12-06 (вес 0): Q = 0, заявка 0 − 271.5 = −271.5 на 2017-12-07.
8. Продажа 2017-12-07: 271.5 по 182; 271.5 × 182 = 49413.0; выручка 49413.0 × 0.999 = 49363.587; деньги 50438.579 + 49363.587 = 99802.166; позиция 0.

Ожидаемые значения: покупка 1087 по 91, деньги 984.083; NAV решения 2017-12-04 = 99901.083, target_qty 543, order_qty после сплита −272, filled_qty 272; продажа 272 по 182, выручка 49454.496, деньги 50438.579, позиция 271.5; последняя заявка held_qty 271.5, order_qty −271.5, продажа 271.5 по 182, выручка 49363.587, деньги 99802.166, позиция 0; `split_events == [['BBB', '2017-12-05']]`.

## Случай 3. Ex-date и дата выплаты

Вход: тикеры DDD и EEE, close и open 49 во все сессии; у обоих dividend 1.0 на ex-date 2017-11-30, payable_date 2017-12-05, basis actual. Решения: 2017-11-28 (DDD 1), 2017-11-29 (DDD 0, EEE 1), 2017-12-04 (EEE 1).

Расчёт:

1. Решение 2017-11-28: Q(DDD) = floor(0.99 × 100000 / 49) = floor(2020.41) = 2020. Покупка 2017-11-29: 2020 × 49 = 98980.0; издержки 98.98; деньги 100000 − 98980.0 − 98.98 = 921.02.
2. NAV на закрытии 2017-11-29: 921.02 + 2020 × 49 = 99901.02. Решение 2017-11-29: DDD 0, Q(EEE) = floor(0.99 × 99901.02 / 49) = floor(2018.41) = 2018. Заявки: DDD −2020, EEE +2018 на 2017-11-30.
3. Сессия 2017-11-30 (ex-date), шаг 2: у DDD позиция 2020, дебиторка 2020 × 1.0 = 2020.0 со сроком 2017-12-05; у EEE позиции нет, дебиторка не создаётся.
4. Продажа DDD 2020 по 49: 2020 × 49 = 98980.0; выручка 98980.0 × 0.999 = 98881.02; деньги 921.02 + 98881.02 = 99802.04.
5. Покупка EEE 2018 по 49: 2018 × 49 = 98882.0; расход 98882.0 × 1.001 = 98980.882; деньги 99802.04 − 98980.882 = 821.158.
6. NAV на закрытии 2017-11-30: 821.158 + 2018 × 49 + 2020.0 = 821.158 + 98882.0 + 2020.0 = 101723.158.
7. Решение 2017-12-04: Q(EEE) = floor(0.99 × 101723.158 / 49) = floor(100705.926 / 49) = floor(2055.22) = 2055. Заявка 2055 − 2018 = +37 на 2017-12-05.
8. Сессия 2017-12-05, шаг 3: зачисление 2020.0, деньги 821.158 + 2020.0 = 2841.158. Шаг 5: покупка 37 по 49; 37 × 49 = 1813.0; расход 1813.0 × 1.001 = 1814.813; деньги 2841.158 − 1814.813 = 1026.345.
9. NAV на закрытии 2017-12-05: 1026.345 + 2055 × 49 = 1026.345 + 100695.0 = 101721.345.

Ожидаемые значения: деньги 2017-11-29 = 921.02; дебиторка DDD на 2017-11-30 = 2020.0, дебиторки EEE нет (в payouts одна строка, status paid); продажа DDD 2020 с выручкой 98881.02, покупка EEE 2018 с расходом 98980.882, деньги 821.158, NAV 101723.158; заявка 2017-12-04 +37; 2017-12-05: покупка 37 за 1814.813, деньги 1026.345, дебиторка 0, NAV 101721.345.

## Случай 3б. Сценарий proxy_pay_days = 0

Вход: тикер FFF, close и open 41, dividend 0.25 на ex-date 2017-11-30, payable_date 2017-12-11, payable_basis `proxy_ex_plus_10_calendar_days` (2017-11-30 + 10 календарных дней = 2017-12-10, воскресенье; первая сессия не раньше этой даты: 2017-12-11). Решение 2017-11-28, вес FFF = 1.

Расчёт:

1. Q = floor(0.99 × 100000 / 41) = floor(2414.63) = 2414. Покупка 2017-11-29: 2414 × 41 = 98974.0; расход 98974.0 × 1.001 = 99072.974.
2. Ex-date 2017-11-30: дебиторка 2414 × 0.25 = 603.5.
3. Базовый сценарий (k = 10): срок 2017-12-11 позже end_session 2017-12-08; дебиторка остаётся в статусе receivable и входит в NAV; basis `proxy_ex_plus_10_calendar_days`; `proxy_payouts == [['FFF', '2017-11-30', '2017-12-11']]`.
4. Сценарий proxy_pay_days = 0: срок = первая сессия не раньше 2017-11-30 + 0 дней = 2017-11-30; зачисление на шаге 3 той же сессии, деньги увеличиваются на 603.5; basis `proxy_ex_plus_0_calendar_days`; `proxy_payouts == [['FFF', '2017-11-30', '2017-11-30']]`.

Ожидаемые значения: количество 2414; база: status receivable, pay_session 2017-12-11, amount 603.5, дебиторка 603.5 в daily на 2017-12-08; k = 0: status paid, pay_session 2017-11-30, amount 603.5, дебиторка на закрытии 2017-11-30 равна 0. Инварианты проходят в обоих сценариях.

## Случай 4. Гэп и коэффициент исполнения

Вход: тикер GGG, close 97 во все сессии, open 97 во все сессии, кроме 2017-11-29 (open 99). Решение 2017-11-28, вес 1.

Расчёт:

1. Q = floor(0.99 × 100000 / 97) = floor(1020.62) = 1020; заявка +1020 на 2017-11-29.
2. R = 1020 × 99 × 1.001 = 100980.0 × 1.001 = 101080.98.
3. fill = min(1, 100000 / 101080.98) = 0.989306.
4. Куплено floor(0.989306 × 1020) = floor(1009.09) = 1009. Остаток заявки отменён с причиной `insufficient_cash`; status partial.
5. Расход: 1009 × 99 = 99891.0; × 1.001 = 99990.891; деньги 100000 − 99990.891 = 9.109.

Ожидаемые значения: target_qty 1020, куплено 1009 по 99, buy_fill = 100000 / 101080.98, деньги 9.109, status partial, cancel_reason `insufficient_cash`.

## Случай 5. Замена ETF

Вход: тикер HHH, close и open 80; тикер III, close и open 40. Решения: 2017-11-28 (HHH 1), 2017-11-29 (HHH 0, III 1).

Расчёт:

1. Решение 2017-11-28: Q(HHH) = floor(0.99 × 100000 / 80) = floor(1237.5) = 1237. Покупка 2017-11-29: 1237 × 80 = 98960.0; издержки 98.96; деньги 100000 − 98960.0 − 98.96 = 941.04.
2. NAV на закрытии 2017-11-29: 941.04 + 1237 × 80 = 99901.04. Решение 2017-11-29: HHH 0, Q(III) = floor(0.99 × 99901.04 / 40) = floor(2472.55) = 2472. Заявки: HHH −1237, III +2472.
3. Сессия 2017-11-30. Продажа HHH 1237 по 80: 98960.0; выручка 98960.0 × 0.999 = 98861.04; издержки 98.96.
4. Покупка III 2472 по 40: 98880.0; расход 98880.0 × 1.001 = 98978.88; издержки 98.88. Выручка продажи доступна для покупки в ту же сессию (R = 98978.88 при деньгах 941.04 + 98861.04 = 99802.08; fill = 1).
5. Деньги: 941.04 + 98861.04 − 98978.88 = 823.20.
6. Издержки решения 2017-11-29: 98.96 + 98.88 = 197.84. Оборот: (98960.0 + 98880.0) / 99901.04 = 197840 / 99901.04.

Ожидаемые значения: покупка HHH 1237, деньги 941.04, NAV 99901.04; 2017-11-30 продажа HHH 1237 (выручка 98861.04), покупка III 2472 (расход 98978.88), деньги 823.20; costs_usd решения 2017-11-29 = 197.84, turnover = 197840 / 99901.04, buy_fill 1.0.

## Случай 6. Задержка lag = 2

Вход: тикер JJJ, close 97 во все сессии; open 97, кроме 2017-11-29 (open 50) и 2017-11-30 (open 98). Сценарий lag = 2. Решение 2017-11-28, вес 1.

Расчёт:

1. Q = floor(0.99 × 100000 / 97) = floor(1020.62) = 1020; исполнение на второй сессии после решения: 2017-11-30. На 2017-11-29 сделок нет, деньги 100000.0.
2. R = 1020 × 98 × 1.001 = 99960.0 × 1.001 = 100059.96; fill = 100000 / 100059.96 = 0.999401.
3. Куплено floor(0.999401 × 1020) = floor(1019.39) = 1019 по 98.
4. Расход: 1019 × 98 = 99862.0; × 1.001 = 99961.862; деньги 100000 − 99961.862 = 38.138.

Ожидаемые значения: нет сделок 2017-11-29; execution_session 2017-11-30; покупка 1019 по 98; деньги 38.138.

## Случай 6б. Заявка без валидного Open

Вход: тикер KKK, close 97 во все сессии; open 97, кроме 2017-11-29 (open не задан, NaN). Решение 2017-11-28, вес 1.

Ожидаемые значения: status cancelled, cancel_reason `no_valid_open`, filled_qty 0.0, сделок нет.
