## Замечания

### R1 — P2: пустая сумма SSGA может удалить существующую выплату

Место: `src/alpha_lab/evidence.py:92–93`; последствие в `src/alpha_lab/corrections.py:38–42`.

В `parse_ssga_xlsx` все пустые денежные ячейки преобразуются в нули через `float(get(n) or 0)`. Строка с заполненной ex-date, но пустыми DIVIDEND / SHORT TERM CAPITAL GAIN / LONG TERM CAPITAL GAIN становится событием с amount=0. Затем compare включает дату в issuer_zero_dates, а derive создаёт remove для имеющейся выплаты Yahoo. Это нарушает D016: отсутствие суммы не является явной нулевой записью.

Воспроизведение: строка TEST от 2017-11-29 с тремя пустыми денежными ячейками и выплата Yahoo 0.1. Парсер вернул 0.0; derive сформировал action=remove, yahoo_amount=0.1, issuer_amount=0.0. Следствие — исчезновение права на выплату и изменение TR при неполном ответе эмитента.

Исправление: полностью отсутствующую сумму отклонять или сохранять отдельный признак неизвестной суммы; удаление разрешать только при явно указанном нуле. Нужен тест всей цепочки parse → compare → derive. В реальном SSGA workbook полностью пустых сумм SPY/BIL не обнаружено; BIL 2022-03-01 содержит явное `0.000000`, поэтому текущее удаление этим дефектом не затронуто.

### R2 — P2: corrections без payable теряет известную дату выплаты

Место: `src/alpha_lab/normalize.py:124–133`; допускающий вход — `src/alpha_lab/pipeline.py:180–182` и необязательный CLI-флаг `--payable`.

Correction содержит payable_date и source, но нормализация выбирает дату исключительно из отдельного payable. Команда audit с `--corrections .../corrections.json` без `--payable` принимается. При отсутствии отдельной записи даже подтверждённая дата из correction заменяется ex+10, что нарушает приоритет actual по протоколу и меняет доступность денег для N2.

Воспроизведение: replace для TEST, ex-date 2017-11-29, payable_date 2017-12-01. При передаче только corrections результат — payable_date 2017-12-11, basis=proxy_ex_plus_10_calendar_days. Ошибки не возникает.

Исправление: использовать подтверждённую payable_date из correction, автоматически подключать соответствующий payable.json либо явно отказывать, если обязательная связанная информация не передана. Проверять конфликт двух actual дат. Текущий итоговый запуск передал оба файла; его даты этим сценарием не затронуты.

### R3 — P2: reconcile принимает исправления от другого снимка

Место: `src/alpha_lab/reconcile.py:113–117`.

Reconcile проверяет corrections_info, но не вызывает check_vintage_lineage. Проверка происхождения уже есть в audit. Поэтому один и тот же набор входов может получить confirmed при сверке и отказ при последующем audit.

Воспроизведение: corrections получены из снимка A; снимок B имеет другие metadata/retrieved_at и другой manifest hash при тех же суммах событий. Reconcile(B, corrections_A) завершился и подтвердил исправленный тикер. Audit(B, corrections_A) корректно отказал: corrections vintage was derived from another source snapshot. Это случай смешивания версий данных, не предположение о злонамеренной подделке.

Исправление: перед normalized вызвать ту же проверку происхождения по проверенному source manifest hash. Добавить регрессионный тест для reconcile и failed-события журнала. У реального итогового vintage хеш источника совпадает; обнаруженный сценарий не означает, что текущие версии смешаны.

### R4 — P2: подтверждение отсутствия распределений не требует файлов документов

Место: `src/alpha_lab/reconcile.py:18–21` и `49–52`.

Для kind=document функция issuer_events делает continue до проверки соответствия file/sha256 списку файлов manifest. Далее no_distribution_sources использует metadata без этой проверки. Сам verify проверяет перечисленное содержимое снимка, но не семантическую ссылку metadata на документ.

Воспроизведение: валидный по хешам evidence-снимок сохраняет metadata GLD с ссылками gld.pdf/gld-faq.pdf, но эти PDF не входят в его files. Reconcile принимает такой внутренне несогласованный снимок и выдаёт confirmed_no_distributions со ссылками на отсутствующие документы.

Исправление: проверять наличие и совпадение хеша для всех источников, включая document, прежде чем использовать no_distributions. Отдельные тесты на отсутствующий документ и несовпадающий sha256. В текущем реальном evidence оба PDF присутствуют; их проверка целостности прошла.
