## Findings at the reviewed version

### R1 — P2: a missing SSGA amount can remove an existing distribution

Location: `src/alpha_lab/evidence.py:92–93`; downstream effect in `src/alpha_lab/corrections.py:38–42`.

parse_ssga_xlsx converts all blank monetary cells to zero via `float(get(n) or 0)`. A row with an ex-date but blank DIVIDEND / SHORT TERM CAPITAL GAIN / LONG TERM CAPITAL GAIN becomes an event with amount=0. compare then includes the date in issuer_zero_dates, and derive creates a remove correction for an existing Yahoo distribution. This violates D016: a missing amount is not an explicit zero.

Reproduction: a TEST row dated 2017-11-29 with three blank monetary cells and a Yahoo distribution of 0.1. The parser returned 0.0; derive generated action=remove, yahoo_amount=0.1, issuer_amount=0.0. An incomplete issuer response could therefore remove a payment entitlement and change TR.

Required fix: reject a wholly missing amount or preserve an explicit unknown-amount flag, permitting removal only for an explicit zero. Test the complete parse → compare → derive chain. The real SSGA workbook contained no wholly missing SPY/BIL amounts; BIL 2022-03-01 has explicit `0.000000`, so the saved removal was unaffected.

### R2 — P2: corrections without payable input lose a known payment date

Location: `src/alpha_lab/normalize.py:124–133`; accepting entry point in `src/alpha_lab/pipeline.py:180–182` and optional CLI flag `--payable`.

A correction contains payable_date and source, but normalization selects the date exclusively from separate payable input. audit accepts `--corrections .../corrections.json` without `--payable`. Without a separate record, even a confirmed correction date becomes ex+10, violating the protocol's actual-date priority and changing cash availability for N2.

Reproduction: replace for TEST, ex-date 2017-11-29, payable_date 2017-12-01. With corrections alone, the output is payable_date 2017-12-11, basis=proxy_ex_plus_10_calendar_days. No error occurs.

Required fix: use the confirmed payable_date from the correction, automatically load its associated payable.json, or explicitly reject missing required associated information. Validate conflicting actual dates. The saved final run supplied both files; its dates were unaffected.

### R3 — P2: reconcile accepts corrections from another source snapshot

Location: `src/alpha_lab/reconcile.py:113–117`.

Reconcile validates corrections_info but does not call check_vintage_lineage. audit already checks provenance. The same inputs can therefore receive confirmed during reconciliation and be rejected by subsequent audit.

Reproduction: corrections originate from snapshot A; snapshot B has different metadata/retrieved_at and manifest hash but the same event amounts. Reconcile(B, corrections_A) completed and confirmed the corrected ticker. Audit(B, corrections_A) correctly rejected it: corrections vintage was derived from another source snapshot. This is a data-version mix-up scenario; it does not require deliberate tampering.

Required fix: call the same lineage check using the verified source manifest hash before normalized. Add a reconcile regression test and assert a failed journal event. The real final vintage's source hash matches; this finding does not establish a version mix-up in the saved data.

### R4 — P2: no-distribution confirmation does not require the document files

Location: `src/alpha_lab/reconcile.py:18–21` and `49–52`.

For kind=document, issuer_events continues before checking file/sha256 against the manifest file list. no_distribution_sources subsequently uses metadata without that check. verify validates listed snapshot contents but not the metadata's semantic reference to a document.

Reproduction: an evidence snapshot with valid hashes retains GLD metadata referencing gld.pdf/gld-faq.pdf, while those PDFs are absent from its files. Reconcile accepts the internally inconsistent snapshot and returns confirmed_no_distributions with references to missing documents.

Required fix: verify file presence and matching hashes for every source, including document, before using no_distributions. Test a missing document and mismatched sha256 separately. Both PDFs are present in the actual evidence snapshot and passed integrity verification.
