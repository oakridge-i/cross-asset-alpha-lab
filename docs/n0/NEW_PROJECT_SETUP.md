## Что сделать пользователю

1. Открыть новый чат для Cross-Asset Alpha Lab с отдельным каталогом проекта. Предложение: <workspace>\cross-asset-alpha-lab. Проверить, что имя свободно; каталог AAPL для нового проекта не использовать.
2. Передать содержимое NEW_CHAT_BRIEF.md первым сообщением. Все файлы подготовки лежат в <workspace>\quant-research-plan.
3. Поручить агенту выполнить N0 полностью. Он создаст локальный репозиторий, перенесёт шаблон инструкций и план, заведёт документы и проверит источники данных.
4. Дальше задавать конкретные этапы или изменения. Постоянно обновлять README и инструкции вручную не требуется: это входит в работу агента.

Для проверочного чтения AAPL доступны C:\Quantitive\model 1 aapl и <workspace>\aapl-finalization. Рабочий каталог нового чата должен быть отдельным. GitHub-публикация нового репозитория — отдельное разрешение.

## Документы и ответственность

| Файл нового репозитория | Назначение | Когда агент обновляет |
|---|---|---|
| AGENTS.md | Краткие постоянные правила работы и исследования | При изменении правил; не после каждого прогона |
| README.md | Цель, текущее состояние, установка и воспроизведение | Когда меняются возможности, команды или главный результат |
| STATUS.md | Текущий этап, проверки, ограничения, следующий шаг | После каждой завершённой задачи и при остановке работы |
| DECISIONS.md | Существенные решения, причины и изменения прежних решений | Когда принимается новое решение |
| docs/MASTER_PLAN.md | Общий маршрут N0–N8 | При согласованном изменении объёма или порядка этапов |
| RESEARCH_PROTOCOL.md | Гипотезы, параметры, выбор, разбиения, критерии проверки | Версия до экспериментов; последующие изменения с историей |
| DATA_CONTRACT.md | Поля, время доступности, корректировки, пропуски | N1 и при изменении источника/семантики |
| EXECUTION_MODEL.md | Порядок событий, заявки, сделки, расходы и денежные ограничения | N2 и при изменении исполнения |
| experiments/EXPERIMENT_LOG.jsonl | Машинно читаемый реестр всех попыток и запусков | Каждая попытка/запуск, включая неудачи |
| FINAL_REPORT.md | Выводы, доказательства, неопределённость и воспроизведение | После завершения исследовательской кампании |

AGENTS.md поместить в корень проекта: Codex использует его как источник инструкций. Остальные документы агент читает по указаниям AGENTS.md и текущей задаче. Не хранить длинный журнал прогонов в постоянных инструкциях.

Официальное описание: https://learn.chatgpt.com/docs/agent-configuration/agents-md.

## Что должно быть готово к концу N0

- Проверены источники, покрытие, доступность корпоративных действий и ограничения использования; неизвестное явно записано.
- Зафиксированы universe и исторические окна по доступности данных. Прежний просмотр периодов отмечен; статус финального теста обоснован.
- Записаны точные формулы H1/H2, четыре базовых сравнения, риск/денежная часть, расходы, задержки и шесть конфигураций.
- Определены критерий выбора, обработка близких результатов, минимально интересный экономический эффект, статистические проверки и правила отказа от гипотезы.
- Различаются фиксированные конфигурации и отдельная политика адаптивного выбора; учтены все исследовательские попытки.
- Созданы AGENTS.md, README.md, STATUS.md, DECISIONS.md, RESEARCH_PROTOCOL.md, docs/MASTER_PLAN.md и журнал попыток.
- В STATUS.md указано, что N0 завершён, по каким свидетельствам и какая конкретная задача N1 следующая. Если данные не позволяют исполнить исходный план, решение записано до оптимизации сигналов.

## Простое правило для будущих сообщений

Пиши цель, границы текущего этапа и желаемый результат. Например: «Выполни N1 полностью по протоколу. Проверь данные, сохрани снимок и отчёт качества, обнови STATUS.md и DECISIONS.md. Поиск параметров пока не запускай».

Тебе достаточно исправлять цели и предпочтения. Агент поддерживает техническую документацию и доказательства выполнения в репозитории, чтобы следующий чат мог продолжить работу по файлам.
